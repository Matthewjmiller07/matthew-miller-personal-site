Field notes

What actually goes wrong building this

Every app here was built in conversation with Claude, a session at a time. The interesting parts were never the happy path.

[DREO FAN]
Two hours convinced the fan integration had a memory leak on the ESP32. It didn't — Dreo's cloud API nests a "user manual" link ten layers deep in its device-list response, past ArduinoJson's default parsing depth. Raising one number (NestingLimit) fixed what looked exactly like a hardware problem.
[LAUNCHER]
Arduino silently auto-generates a function prototype for almost every function across every file in the sketch — except one you've already declared yourself. Redeclaring one ordinary, no-argument function as a defensive habit quietly suppressed its real prototype sketch-wide, and broke every app compiled before it in the file order. Took a full afternoon to isolate.
[KLEZMER]
Rule now bolted to the workflow: never transcribe a melody from memory into code. The contour comes out subtly wrong every time, and it's audible immediately on a buzzer. Every tune on the device was pulled from a real MIDI or ABC notation source and transposed by script, not hummed and guessed.
[HARDWARE]
The device fully powers itself off — not sleeps, off — after 10 idle seconds, to save the battery. Which means "just reflash it real quick" usually starts with finding the power button.
